# 当前交接约定
## 数据
- pipe_id：原始 ID 的字符串形式，是空间数据、属性、模型结果的关联键。
- pipe_code：原始 BH 编号，页面用于阅读和检索。
- 当前源：data/network.json（属性与来源）、data/geometry.json（相对平面米制几何）。
- 当前4档分级：高、较高、中、低；缺失评分预留“未评估”，禁止自动归低。
- 本版只采用提供资料里的 RISK 评分，未训练新模型。

## 接口
GET /api/dashboard：meta、filters、summary、pipes。列表不含 factors/recommendation 以减小体积。
GET /api/pipes/{pipe_id}：完整详情。
GET /api/network：原始平面坐标平移后的几何、全域范围和道路标注。
GET /api/export：按同样筛选导出，并可指定逗号分隔的 ids。
筛选参数 q、risk、material、min_diameter。统计、地图着色和导出必须使用同一已应用筛选。
全域淡色几何作为空间背景；筛选外管段不能被点选。

## 地图组件
PipeMap.vue 接收 network、pipes、selectedId、filters，发出 pipe-select（字符串 ID）与 expand。
暴露 fit() 与 focusSelected()。
network.features：id、lines（多段折线）、bounds、diameter、road、road_type、risk、length。
network.extent：局部平面范围，单位米。该格式不是经纬度 GeoJSON；接正式 GIS 时由空间负责人明确转换。
当前道路名称来自管段属性，道路类型开关只是线条分类，不是独立道路矢量图层。

## 后续模型交付
至少提供 pipe_id、score（注明定义）、level、评估时点、模型版本、主要影响因素及其解释依据。
如输出事故概率，独立字段并明确预测事件和时间窗口，不可将0–100分直接除以100。
接入后更新 meta.score_source、score_note、grading_note 与界面来源说明，同时验证已匹配ID比例。
模型验证结果与 SHAP 等归因结果当前均未提供；不填造精度或贡献度。

## 学习入口
App.vue 中 load() 负责列表筛选，getDetail() 负责选中管段后的详情。
PipeMap.vue 中 draw() 渲染几何，pick() 识别点击，pipe-select 将ID传回页面。
后端 main.py 负责数据查询与CSV导出；导入脚本负责空间关联与字段整理。
